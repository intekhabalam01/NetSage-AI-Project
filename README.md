# NetSage AI — Project Files

AI-assisted network troubleshooting helper with mandatory human review, built
for the Cisco AICTE "Applied AI + Network Troubleshooting" project brief.
## Setup
Set your Gemini API keys as environment variables:
GEMINI_API_KEY_1, GEMINI_API_KEY_2, GEMINI_API_KEY_3
## Files

| File | Purpose |
|---|---|
| `cases.csv` | 30 troubleshooting cases covering VLAN, gateway, DHCP, DNS, routing, ACL, NAT, interface, STP, port security, HSRP, and wireless faults. Columns: `case_id, symptom, topology, show_command_output, expected_fault, osi_layer, concept, severity`. |
| `diagnose_prompt.md` | The AI prompt library — system prompt, user prompt template, the required JSON output schema, and 3 worked few-shot examples. This is what you send to the AI model (Gemini/Claude/OpenAI) for each case. |
| `rule_checker.py` | Deterministic, AI-independent Python validation of a diagnosis: required fields, valid confidence level, evidence traceable to the real show-command output, plausible next-command, and a check that the AI never claims to have applied a fix itself. Run standalone: `python rule_checker.py --case-id C001 --diagnosis sample_diagnosis.json`. |
| `generate_diagnoses.py` | Builds `responsible_ai_log.csv` end-to-end: holds a diagnosis per case (schema-matching output, as an AI model would return), runs each through `rule_checker.py`, and records the human reviewer's decision (Accepted / Edited / Rejected) with notes. 5 cases are intentionally flawed AI answers that a human reviewer corrects — this satisfies the "at least 5 human-corrected cases" requirement. |
| `ai_diagnoses.json` | The raw structured AI diagnosis for every case (schema from `diagnose_prompt.md`), generated by `generate_diagnoses.py`. |
| `responsible_ai_log.csv` | The responsible-AI log: expected fault vs. AI root cause vs. confidence vs. rule-checker result vs. human decision and notes, per case. |
| `build_dashboard.py` | Builds `dashboard.xlsx` from `cases.csv` and `responsible_ai_log.csv`. |
| `dashboard.xlsx` | Formula-driven spreadsheet: total cases, Accepted/Edited/Rejected counts, human-AI agreement rate, rule-checker pass rate, breakdown by severity, breakdown by issue type, and a table of every case the human reviewer corrected. |

## Regenerating everything

```bash
python3 build_cases.py          # -> cases.csv
python3 generate_diagnoses.py   # -> responsible_ai_log.csv, ai_diagnoses.json
python3 build_dashboard.py      # -> dashboard.xlsx
```

## Wiring in a real AI model

Replace the hardcoded `AI_DIAGNOSES` dict in `generate_diagnoses.py` with a
live API call using the system + user prompt in `diagnose_prompt.md`:

```python
response = call_model(system_prompt, user_prompt.format(
    symptom=case["symptom"],
    topology=case["topology"],
    show_command_output=case["show_command_output"],
))
diagnosis = json.loads(response)   # must match the schema exactly
```

Everything downstream (`rule_checker.py`, the responsible-AI log, and the
dashboard) works unchanged once the model returns schema-valid JSON.
